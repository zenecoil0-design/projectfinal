ปรับคู่มือ 3 พฤศจิกายน 2569 จากโค้ด `ba0f7638959f578a407632a4a2d5586de68acbfe` คู่กับ [คู่มือผู้ใช้](USER_GUIDE.md) และ [ขอบเขตส่งจบล่าสุด](FINAL_DELIVERY_SCOPE.md) รอบนี้ตรวจเอกสาร/โค้ดเท่านั้น **ยังไม่ได้เปิด UI ทดลอง ถ่ายภาพ หรือซ้อมบนเครื่องเจ้าของ** ตารางสิ่งที่ควรเห็นและภาพด้านล่างเป็นเกณฑ์สำหรับซ้อม ไม่ใช่ผลผ่าน

**อัปเดต 6 พ.ย. 2569:** ตั้งแต่ commit `3849f4c` แอป**ไม่มี feature flag แล้ว** Snapshot, ทำสำเนา/ลบพอร์ต และกรอกอายุเอง เปิดถาวร ไม่ต้องเพิ่มบรรทัด `NEXT_PUBLIC_..._ENABLED` ใด ๆ (ถ้ามีค้างใน `.env.local` ลบทิ้งได้ ไม่มีผล) ส่วนบทซ้อมด้านล่างยังเป็นเกณฑ์ ไม่ใช่ผลผ่าน

ใช้ checkout ของแอปที่เปิดใน VS Code และรันเว็บจริง ไม่ใช่ worktree สำหรับ Docker เพียงอย่างเดียว

## 1. เตรียมเครื่องและบัญชีก่อนเริ่มจับเวลา

1. ตรวจ `git status --short` และ branch ปัจจุบันก่อนดึง `codex/portfolio-next-phase` หากมีงานแก้ค้างให้เก็บก่อน ไม่ reset ทิ้งงาน
2. ใน `.env.local` ข้าง `package.json` ต้องมีเพียง URL/key ของ Supabase ที่ใช้อยู่ ตามตัวอย่าง [`.env.example`](../.env.example) ไม่ต้องมี flag เพิ่ม
3. หยุด dev server ด้วย Ctrl+C แล้วรัน `npm run dev` ใหม่ เปิด URL ที่ terminal แสดง ถ้าใช้ production ให้ `npm run build` (สคริปต์ใช้ webpack ตามที่ตรวจมาตลอด) ก่อน `npm start`
4. ปุ่มทำสำเนา/ลบพอร์ตและช่อง “กรอกอายุเอง” แสดงเสมอเมื่อโหลดรายการพอร์ตและยืนยันบัญชีสำเร็จ หากไม่ปรากฏหรือมี error ให้ผู้ดูแลตรวจ configuration/session ไม่ติดตั้ง migration ซ้ำจากคู่มือนี้ พอร์ตเก่าที่ยังไม่มีฉบับเริ่มต้นจะเห็นหน้า **ฉบับข้อมูลของพอร์ต** ให้อ่านแล้วกด **ยืนยันเตรียมฉบับเริ่มต้น** หนึ่งครั้ง

localhost ยังต่อ Supabase ผ่านอินเทอร์เน็ต ไม่ใช่ระบบ offline และไม่ต้องเปิด Docker เพื่อใช้แอปตาม configuration นี้ Docker ใช้กับ isolated integration tests การพิมพ์ localhost **ไม่ได้แปลว่าฐานหรือ Storage แยกจาก hosted**

ก่อนนำเสนอให้ผู้ดูแลยืนยันสภาพแวดล้อมที่อนุญาตและ feature ที่พร้อมแล้ว (Snapshot เปิดในแอปเสมอแล้ว ไม่ต้องเปิดเพิ่มจากคู่มือนี้) หยุดบทที่ต้องใช้หากฐาน/สิทธิ์/ปุ่มยังไม่พร้อม ไม่สาธิตผลจำลองว่าเป็นระบบจริง

- ใช้บัญชีสาธิตที่ได้รับอนุญาต ตั้งชื่อ/ประวัติ/โรงเรียนเป็นข้อมูลสมมติ รหัสผ่านและลิงก์กู้รหัสเก็บนอกเอกสาร/ภาพ
- ทดลอง login ก่อนวันนำเสนอ หากต้องโชว์สมัคร/กู้รหัส ให้แยกซ้อมกับอีเมลทดสอบที่รับได้จริง ไม่กรอกอีเมลผู้อื่นหรือรับรองผลส่งอีเมลโดยยังไม่ได้ตรวจ
- เตรียมรูปสังเคราะห์ เช่น รูปทรง/ป้าย “DEMO” แนวตั้งและแนวนอน ไม่ใช้บัตรประชาชน ใบประกาศหรือภาพบุคคลจริง รูปเล็กไม่เกินเกณฑ์ของฟอร์ม ไม่ต้องสร้างไฟล์ 14 MB
- ใช้ชื่อพอร์ตขึ้นต้น `DEMO-` เพื่อลดโอกาสเลือกผิด ถ้าเตรียมข้อมูลไว้แล้ว ให้ใช้รายการเพิ่มใหม่ที่มีชื่อรอบซ้อมชัดเจน ไม่ล้างข้อมูลเก่าเพื่อเริ่มใหม่
- ทดสอบไมค์/ขนาดหน้าจอ/การเปิด PDF ก่อนเริ่ม จัดการแจ้งเตือนหรือข้อมูลบัญชีที่อาจติดภาพ

## 3. ซ้อมลบ — แยกจากบทหลัก และเฉพาะระบบทดสอบที่ยืนยันแล้ว

งานเอกสารนี้ **ไม่มีการลบรายการ/พอร์ต/Storage บน hosted project** ขั้นตอนต่อไปเป็นบทให้เจ้าของซ้อมภายหลังในระบบ local/isolated ที่ผู้ดูแลยืนยันว่ามีข้อมูลสังเคราะห์เท่านั้น:

1. เปิดกล่องลบสำเนา B แล้วกด **ยกเลิก** ก่อน ตรวจว่า B ยังอยู่
2. เมื่อต้องทดสอบลบจริง ให้ลบเฉพาะสำเนาทดลอง ตรวจชื่อก่อน **ลบพอร์ต** หลังยืนยัน A และรายการคลังต้องยังอยู่ ไม่อ้างผลลบไฟล์ Storage
3. หากทดสอบลบคลัง ให้สร้างรายการชื่อ `DEMO-ลบทดสอบ` เพิ่มแยกไว้ ใช้ในพอร์ตทดสอบสองฉบับ และซ่อนหมวดในฉบับหนึ่ง อ่านรายชื่อผลกระทบแล้วเลือก **ยกเลิก** ก่อน
4. เฉพาะเมื่ออยู่ในระบบทดสอบที่ยืนยันแล้ว จึงกด **ลบจากคลังและทุกพอร์ต** เปิดพอร์ตใหม่ตรวจว่ารายการหายทั้งสองฉบับ แม้หนึ่งฉบับซ่อนหมวดไว้
5. ถ้าผลไม่แน่นอน ให้ **ตรวจสอบสถานะ** / **ตรวจสอบผลคำขอค้าง** ก่อนส่งซ้ำ ไม่อ้าง rollback จาก network error

หากยังมีเพียง localhost ที่ต่อ hosted ให้ข้ามการยืนยันลบจริง ใช้ชี้ผลกระทบและยกเลิกแทน แล้วบอกขอบเขตที่ยังไม่ได้สาธิต

สถานะ 5 พ.ย.: ติดตั้งบนฐานเป้าหมายแล้ว เจ้าของรายงานเส้นทางกิจกรรม 7 ขั้นตอนผ่านบน localhost ที่เชื่อมฐานจริง ดู [บันทึกติดตั้งและข้อจำกัด](SNAPSHOT_RELEASE_RUNBOOK.md) บทนี้เพิ่มเวลาอีก 5–7 นาทีจากบทหลัก และใช้เฉพาะเว็บที่ผู้ดูแลเปิด Snapshot แล้ว

เมื่อได้รับการยืนยันแล้วจึงแยกซ้อมประมาณ 5–7 นาที:

1. ใช้รายการและพอร์ตสังเคราะห์ A/B เตรียม snapshot ของฉบับเดียวกัน หากพบหน้า **ฉบับข้อมูลของพอร์ต** อ่านและกด **ยืนยันเตรียมฉบับเริ่มต้น** เฉพาะเมื่อยอมรับว่ากำลังใช้ข้อมูลปัจจุบัน ไม่ใช่กู้ย้อนหลัง
2. บันทึกข้อความและรูปฉบับแรกในทั้ง A/B จากนั้นแก้รายการในคลังเป็นฉบับใหม่และบันทึก เปิด A/B ใหม่ ทั้งคู่ควรยังแสดงฉบับที่รับไว้ก่อนหน้า รวมรูปเดิม
3. ใน A กด **รับอัปเดตรายการนี้** และยืนยัน ตรวจว่าข้อความกับรูปเป็นฉบับใหม่ชุดเดียวกัน ส่วน B ยังคงเดิม
4. ทำสำเนา B ตรวจว่าสำเนารักษาฉบับของ B ไม่รับฉบับล่าสุดจากคลังแทนเอง
5. เก็บภาพเปรียบเทียบ A/B และ PDF ของแต่ละฉบับหลังตรวจจริง ระบุว่าเป็นบทหลังติดตั้ง อย่านำภาพจากการ mock มาอ้าง hosted
6. หากยังยืนยันผลไม่ได้ ใช้ **ตรวจสอบฉบับปัจจุบัน** ไม่รับซ้ำอัตโนมัติ ไม่มีหน้ากู้คืนทุกเวอร์ชันในอดีตให้สาธิต

การลบรายการต้นทางยังนำ snapshot ที่อ้างถึงออกจากทุกพอร์ต รวมสำเนา/หมวดซ่อน การเอาออกเฉพาะพอร์ตไม่ลบคลัง ลบพอร์ตไม่ลบคลัง และลบรายการไม่เท่ากับยืนยัน cleanup Storage

## 5. ข้อจำกัดที่ต้องพูดตามจริงและประเด็นส่งไค

- คำนำ โปรไฟล์ และข้อความในการ์ดสามหมวดแบ่งข้ามหน้าได้แล้ว แต่รูปหรือองค์ประกอบที่ยังจัดลงหน้าไม่ได้ยังถูก overflow guard บล็อก จำนวนหน้าไม่จำกัดตามกติกาผลิตภัณฑ์ไม่ได้รับประกันทรัพยากรเบราว์เซอร์ไม่สิ้นสุด
- ไฟล์เกิน 10 MB ต้องอ่านขนาดจริงและยืนยัน **ดาวน์โหลดต่อ** / **ยกเลิก** หากไม่ได้สร้างกรณีนี้ในการซ้อม อย่ารายงานว่าทดลองแล้ว
- การรับอีเมลกู้รหัสจริงขึ้นกับสภาพแวดล้อม ต้องตรวจบัญชี/อุปกรณ์ที่ได้รับอนุญาตก่อนวันนำเสนอ
- Snapshot ติดตั้งแล้ว แต่ hosted acceptance อีกสองหมวด หมวดซ่อน และสิทธิ์ข้ามบัญชียังต้องตรวจ ไม่เหมารวมจากผลกิจกรรม
- Autosave และเลือกรูปย่อยรายพอร์ตเป็น **REMOVED** ตาม 28 ต.ค. ไม่ใช่งานเลื่อนรอบส่ง ส่วน Snapshot เป็นงานหลักที่ติดตั้งแล้วและยังตรวจรับไม่ครบทุกเส้นทาง
- checklist เดิมที่บอกสามเรื่องนี้เป็นงานเลื่อน แก้ให้ตรงขอบเขตล่าสุดแล้ว แต่คงผลตรวจและรายงานเดิมเป็นประวัติ
- ประวัติ 3 พ.ย. (สถานะก่อนติดตั้ง ไม่ใช่สถานะล่าสุด): ไคตรวจทานต่อจากงาน Sol วันที่ 3 พ.ย. และแก้ตาราง Snapshot ใน `FINAL_DELIVERY_SCOPE.md` แล้ว: มีโค้ดหลังการควบคุมเปิดใช้และหลักฐาน local API แต่ยังรอการรักษารูป ชุดติดตั้ง และ hosted integration ไม่ถือว่าเปิดใช้จริงแล้ว

### หลักฐานและขอบเขตการตรวจรอบเอกสารนี้

ตรวจชื่อปุ่ม เส้นทาง และเงื่อนไขกับโค้ดที่ระบุใน [คู่มือผู้ใช้](USER_GUIDE.md) ตรวจลิงก์ภายในและ whitespace ใน diff เท่านั้น ไม่รัน build/browser/database tests ไม่ต่อฐานหรือ Storage จริง ไม่สร้างบัญชี ไม่ถ่ายภาพหรือส่งออก PDF ใหม่ และไม่ยกผลเก่ามาเป็นผลตรวจรอบนี้

ผล 18/18 และข้อมูลหลัง migration ที่เคยอ้างเป็น checkpoint ก่อนหน้า ดู [รายงานตรวจรับ localhost 27 ต.ค.](verification/LOCALHOST_CORE_ACCEPTANCE_2026_10_27.md) ส่วนสถานะใหม่ให้อ่าน [ขอบเขตส่งจบ](FINAL_DELIVERY_SCOPE.md) และรายงานที่เชื่อมไว้ ไม่เปลี่ยนประวัติ mock/PGlite/local API ให้เป็นผล hosted และไม่ประกาศว่าระบบทั้งหมดเสร็จแล้ว
