เอกสารนี้เป็นข้อกำหนดปัจจุบัน แทนข้อความที่ขัดกันในเอกสารวันที่ 23 ตุลาคมและก่อนหน้า รวม PRD, ARCHITECTURE, DESIGN_SYSTEM, IMPLEMENTATION_PLAN และ SYSTEM_TEST_PLAN เฉพาะเรื่องขอบเขตด้านล่าง ไม่เปลี่ยนผลทดสอบเก่าเป็นผ่าน ไม่ประกาศว่าฟีเจอร์ใหม่ติดตั้งแล้ว

## Snapshot/Version แบบจำกัดขอบเขตเพื่อให้จบงาน

แนวทางดำเนินงานที่เลือก: เก็บฉบับปัจจุบันของรายการในแต่ละพอร์ต พร้อมเวอร์ชันต้นทางและการรับอัปเดต ไม่เพิ่มหน้าประวัติ/restore ทุกเวอร์ชัน ไม่เพิ่ม realtime หรือระบบแก้ conflict แบบเต็มระบบ

1. ครอบคลุมการศึกษา กิจกรรม เกียรติบัตรจากคลัง หน้าปก/คำนำ/โปรไฟล์ยังเป็นข้อมูลรายพอร์ตตามเดิม
2. เมื่อเลือกและบันทึกรายการ ให้เก็บข้อมูลที่แสดง รูปทั้งหมดและลำดับรูป พร้อมตัวระบุเวอร์ชันที่สอดคล้องกัน ข้อมูลกับรูปต้องมาจากฉบับเดียวกัน
3. การแก้คลังไม่เปลี่ยนพอร์ต A/B หรือ PDF ที่สร้างใหม่จาก snapshot เดิมโดยอัตโนมัติ แม้ reload รูปเดิมที่ยังอ้างต้องอยู่ครบ
4. แสดงว่ามีฉบับใหม่เมื่อยืนยันได้ ผู้ใช้กดรับอัปเดตเฉพาะรายการเอง ไม่โหลดมาทับ draft เงียบ ๆ และไม่เปิดตัวเลือกรูปย่อย
5. การรับอัปเดตต้องมีสถานะสำเร็จ/ล้มเหลว/ผลไม่แน่นอนที่ตรงหลักฐาน เก็บฉบับเดิมหากยังไม่ยืนยัน ป้องกันคำตอบจาก session เก่า และไม่ทำเนื้อหากับรูปคนละเวอร์ชันเมื่อคลังถูกแก้พร้อมกัน
6. ทำสำเนาพอร์ตต้องคัดลอก snapshot ของต้นฉบับจริง ไม่เปลี่ยนเป็นฉบับล่าสุดในคลัง การรับอัปเดตในสำเนาไม่เปลี่ยนต้นฉบับ
7. รักษาคำสั่งลบคลังเดิม: แจ้งผลกระทบ/ยืนยัน แล้วนำรายการและ snapshot ที่อ้างต้นทางนั้นออกจากทุกพอร์ตเจ้าของ รวมพอร์ตสำเนาและหมวดซ่อน Snapshot ไม่ใช่วิธีกู้รายการที่ลบจากคลัง
8. เอารายการออกจากพอร์ตกระทบเฉพาะพอร์ตนั้น ลบพอร์ตไม่ลบคลัง รูปที่ snapshot หรือส่วนอื่นยังใช้ต้องไม่ถูก cleanup
9. พอร์ตเดิมต้องมีแผนเปลี่ยนผ่านที่ไม่ทำ selection/order/visibility/สีหาย เมื่อสร้าง snapshot ครั้งแรกจากข้อมูลปัจจุบัน ต้องไม่อ้างว่ากู้เนื้อหาในอดีตที่ไม่เคยเก็บได้

โครงตาราง/RPC/วิธีระบุ revision ต้องตรวจ schema และเส้นทางเขียนจริงก่อนออก migration ไม่อนุญาตให้ reset ฐานหรือติดตั้ง migration ใหม่จากเอกสารนี้โดยอัตโนมัติ

## ลำดับงานที่เหลือเพื่อปิดโครงการ

1. **Snapshot data contract และฐานข้อมูล:** ตรวจทุกเส้นทางเขียนรายการ/รูป, ownership, revision/atomic capture, การย้ายพอร์ตเดิม, copy/delete cascade แล้วพิสูจน์ด้วย unit และ PostgreSQL/PostgREST ก่อนติดตั้งตามขั้นตอนที่ได้รับอนุญาต
2. **เชื่อม Editor/Preview/PDF:** อ่านฉบับที่พอร์ตบันทึก แสดงสถานะมีฉบับใหม่ รับอัปเดตแบบ manual และทดสอบข้อมูล/รูป/dirty/session/เลขหน้า/สารบัญ/สามเทมเพลต
3. **Storage และ integration:** เพิ่ม snapshot เข้าแหล่งอ้างอิงก่อนจับคู่/ลบไฟล์ ป้องกัน concurrent reference writers ก่อน cleanup จริง; ตรวจอีเมลกู้รหัสผ่านและการทำงานกับฐานจริงตามสิทธิ์ที่ได้รับ
4. **ตรวจรับและส่งมอบ:** ซ้อม flow ด้วยข้อมูลตัวอย่างจริง ตรวจอุปกรณ์ใช้นำเสนอ แก้บั๊กที่กระทบเกณฑ์จบ อัปเดตคู่มือ/ผลตรวจและ branch งาน ไม่เพิ่มฟีเจอร์ใหม่ระหว่างเก็บงาน

ห้ามทำ cleanup จริงบนรายการอ้างอิงชุดเก่าแล้วค่อยเพิ่ม snapshot ทีหลัง เปอร์เซ็นต์ประมาณ 90% ก่อนคำสั่งนี้อ้างขอบเขตเดิม ต้องประเมินใหม่จากงานใหม่นี้ ไม่ยกเป็นหลักฐานความพร้อม
