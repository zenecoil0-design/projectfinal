## ผลตรวจเดิมก่อนผู้ใช้ชี้ชัดแหล่งรูป

ภาพที่ผู้ใช้ส่งไว้แสดงเทมเพลต modern: รูปที่เลือกในฟอร์มหน้าปกปรากฏเป็นพื้นหลัง ส่วนกรอบโค้งยังแสดง `YOUR NEXT CHAPTER.` ซึ่งตรงกับโค้ดเมื่อไม่มีรูปโปรไฟล์

พบในโค้ด `src/components/preview/CoverPreview.tsx`:

| แหล่งข้อมูล | classic | modern |
| --- | --- | --- |
| `coverStore.coverImage` | พื้นหลังทั้งหน้า opacity 20% | พื้นหลังพื้นที่ art opacity 18% |
| `profileStore.profileImage` | รูปในกรอบวงกลม | รูปในกรอบโค้ง |

ทั้งสองรูปมีหน้าที่ต่างกัน ไม่ควรเปลี่ยนการเลือกแหล่งรูปหรือใช้ offset กลบอาการโดยยังไม่ทราบกรอบที่ผู้ใช้ต้องการ

## ผลตรวจรอบนี้

ใช้ Chromium + mock Supabase ไม่ได้เขียนข้อมูลหรืออัปโหลดรูปไป Supabase จริง:

- จำลองรูปแนวตั้ง 400×800, แนวนอน 800×400 และจัตุรัส 600×600 สำหรับทั้งแหล่งภาพปกและโปรไฟล์
- ตรวจ classic และ modern ที่ viewport 1440px และ 390px รวม 12 กรณี
- ขนาด layout กระดาษคง 794×1123px; โทรศัพท์ย่อทั้งหน้าด้วย scale เดียวประมาณ 0.450882
- classic: พื้นหลัง 792×1121px ภายใน border หน้า; รูปโปรไฟล์เท่ากับช่องด้านในกรอบ 216×216px
- modern: พื้นหลังเท่ากับ art 682×478px; รูปโปรไฟล์เท่ากับกรอบ 320×390px
- ภาพทั้งสองชนิดใช้ object-fit: cover และ object-position: 50% 50%; ไม่พบการยืดหรือล้นนอกกรอบ ภาพต่างสัดส่วนถูกตัดขอบตามกรอบเดิม
- ตรวจเส้นทาง crop จริงใน browser: รูปแนวนอนตัดเป็น A4 ได้ JPEG 283×400px แล้วแสดง blob เดียวกันในพื้นหลัง Preview
- ส่งออก PDF ผ่านปุ่มจริงทั้ง classic และ modern จาก viewport มือถือสำเร็จ ตัวอย่างละ 6 หน้า
- render หน้าแรกของ PDF ด้วย Poppler และตรวจภาพ: ขอบกรอบและวงกลมทดสอบคงสัดส่วน ตรงกับ Preview; metadata เป็น A4
- อ่าน container, overflow, object-fit/position, CSS ของเทมเพลต, การย่อใน Paper และ output ของ CropInput แล้ว ไม่แก้ renderer, CSS เอกสาร, crop, upload หรือฐานข้อมูล

## สิ่งที่ต้องชี้ชัดก่อนแก้

ต้องทราบว่าผู้ใช้ต้องการให้รูปจากฟอร์มหน้าปกเข้าไปอยู่ **ในกรอบโค้ง/วงกลม** แทนพื้นหลัง หรือกำลังรายงานการตัดขอบของ **รูปโปรไฟล์ที่อยู่ในกรอบแล้ว**

หากเป็นกรณีหลัง ขอภาพเฉพาะจุดพร้อมระบุเทมเพลตและรูปต้นฉบับ/ผล crop ที่ใช้ เพื่อจำลองอาการเดิม ไม่ถือว่าการตรวจด้วยรูปจำลองยืนยันว่าไม่มีบั๊กในข้อมูลจริงทุกกรณี

ส่วน UI คำนำและประวัติส่วนตัวเป็นงานอิสระ ดำเนินต่อได้ตามขอบเขตที่ผู้ใช้อนุญาต

## ข้อสรุปหลังผู้ใช้ยืนยัน — 16 ตุลาคม 2026

ผู้ใช้ยืนยันว่าต้องการให้รูปจากฟอร์มหน้าปกอยู่ในกรอบโค้ง/วงกลม จึงยืนยันสาเหตุได้ว่า **กรอบใช้แหล่งรูปไม่ตรงกับความต้องการ** ไม่ใช่ขนาดกรอบหรือการ scale ผิด

- เปลี่ยนรูปในกรอบของ classic และ modern ให้ใช้ `coverStore.coverImage` แทน `profileStore.profileImage`
- คงพื้นหลังตกแต่งเดิมที่ใช้ภาพหน้าปกจาง ๆ เพื่อรักษาธีม
- รูปประวัติส่วนตัวยังแยกอยู่ในฟอร์ม/หน้าประวัติส่วนตัว ไม่ถูกแก้หรือคัดลอกทับ
- ปรับ label/คำแนะนำใน CoverForm ให้บอกว่าใช้รูปในกรอบ ไม่แนะนำ crop เป็น A4 สำหรับกรอบนี้
- ไม่แก้ขนาด A4, CSS ของกรอบ, object-fit/position, การย่อ, crop, ระบบบันทึกหรือฐานข้อมูล
- เพิ่ม regression E2E ตรวจรูปสองแหล่งที่ต่างกัน ทั้ง classic/modern, desktop/mobile, PDF, crop และการลบรูปหน้าปกโดยยังรักษารูปโปรไฟล์

ผลตรวจหลังแก้: build ผ่าน; lint เฉพาะไฟล์ที่แก้ 0 errors และ warning เดิมเรื่อง `<img>` 5 จุด; E2E เฉพาะการคงชื่อหน้าปกและแหล่งรูปในกรอบผ่าน 2 ข้อ; ตรวจภาพสามสัดส่วน × สองเทมเพลต × desktop/mobile ผ่าน 12 กรณี รวม crop และ PDF ของทั้งสองเทมเพลต ตรวจภาพ PDF ที่ render แล้วไม่ยืด/ล้น ผลทั้งหมดใช้ mock Supabase ไม่ได้เขียนข้อมูลลงระบบจริง
